# Benchmark versions

The version is `f1pitwall.version.BENCHMARK_VERSION`. It appears in:
- `f1ctl rules` → `benchmark_version`
- the sidecar `ping` reply and the evidence `manifest.json` → `benchmark_version`
- the verifier report → `benchmark_version`, plus `evidence.evidence_benchmark_version` for the version that produced the evidence
- `task.toml` → `[task].version`

Results are comparable only within one version.

## 2.1.0 — opt-in FIA-2026-based power-unit rules (B8, 2026-11-15; branch feature/strategic-scenarios-b8)

**What it is.** It is 2.0.1 plus `pu_rules.py`, enabled only through `integrated.config.with_version(cfg, "2.1.0")`.
- **Verified rule structure** (FIA Section B Issue 07): per-driver allocation, 10/5 cumulative penalties, and B2.5.4b grid formation including back of grid.
- **Synthetic, labelled:** the 8-race allocation scaling (2/2/2), the 8/22 place scaling (4/2, threshold 5), and the team stock (3 per type).
- **Not modelled:** EXH, PU-CE, MGU-K, ancillaries, and pool rotation.

**Unchanged:** everything else equals 2.0.1. With no replacement beyond allocation, 2.1.0 and 2.0.1 seasons score identically.

**2.1.0 amendments before the first evaluation** (branch `feature/reference-2.1.0`, commit `84ed780`). No agent had been evaluated on 2.1.0 before these.
1. **Worn elements.** An element above the wear limit may keep running (USE is always legal) with the published pace and reliability cost, and REPLACE is legal only while the team has stock. Before this, two drivers over the limit with one unit of that type left had no legal joint action, and even the published fallback failed. B8's evaluation never reached that state, so its results are unchanged.
2. **Legacy pool.** The legacy shared free-unit pool is 0 under 2.1.0. Observations had shown `free_units_available: 4`, which does not exist in 2.1.0.
3. **Harbor task.** It is generated with `scripts/make_integrated_task.sh <dest> CHIEF_ONLY 2.1.0`.
   - `mode.json` carries `benchmark_version`.
   - `f1ctl rules` publishes `power_unit_rules` and marks the legacy pool superseded.
   - The instruction gets a 2.1.0 power-unit section.
   - The verifier rejects evidence from another version.
   - The scalar formula is unchanged (`b6-integrated-p0`).

## 2.0.1 — action-schema clarification (B7-P0)

**What changed.** `action_schema` now states that component decisions are a list and that `consumed_reports` is a top-level field, and it gives one format example per phase. This is the same for both teams.

**Unchanged:** mechanics, legal actions and scoring.

## 2.0.0 — integrated modes (B6, 2026-11-14; branch feature/championship-integration)

A separate version for the integrated championship. **1.1.0 is unchanged** and remains the
`SOLO_LEGACY` mode (same task directory, contract, journal v1 and `p0-provisional` reward).

| | 1.1.0 (`SOLO_LEGACY`) | 2.0.0 (`SOLO_COORDINATION`, `TWO_TEAM_COMPETITION`) |
|---|---|---|
| Version source | `f1pitwall.version.BENCHMARK_VERSION` | `f1pitwall.integrated.config.INTEGRATED_VERSION` |
| Contract | `contract_version` 1 | `contract_version` 2: team-local observations, `team_orders`, `engineer_reports`, `tick_id` |
| Race action | `driver_a`, `driver_b` | plus `team_order` (required) and optional `consumed_reports` |
| Journal | v1 | v2 (per-team submissions and observation hashes, Engineer record hashes) |
| Reward | `p0-provisional` | `b6-integrated-p0` (same form; D = published fallback on the same seed) |
| Harbor task | `f1-championship/` | generated by `scripts/make_integrated_task.sh` (`EugeneLJ/f1-championship-integrated`) |

**Unchanged in 2.0.0:**
- tyres, pit loss, SC/VSC model and effects, overtaking, Track A wear/allocation, points;
- with team order `RACE` the integrated race step equals the 1.1.0 step bit for bit.

**New synthetic coefficients:** `fixtures/integrated_coefficients.json` (team-order exchange and defence).

## 1.1.0 — interface clarification (2026-11-14)

**Agent-visible change (in `f1ctl rules` only):**

| Field | 1.0.0 | 1.1.0 |
|---|---|---|
| `race_rules_track_a.published_base_pace` | Keyed by engine-internal identifiers (`Rival 1`…`Rival 6`, `Apex A`, `Apex B`). Observations name the same cars `Orion A`, `Nova B`, …, and the mapping between the two was not published. | Keyed by the observation names (`Apex A`, `Apex B`, `Orion A`, `Orion B`, `Nova A`, `Nova B`, `Vertex A`, `Vertex B`). **The values are identical.** |
| `race_rules_track_a.driver_identifiers` | — | New. `engine_internal_to_public` mapping, plus the team → driver list |
| `benchmark_version` (top level of rules) | — | New. `"1.1.0"` |
| `contract` (description string) | `"f1-championship sequential decisions, P0 mechanics"` | `"f1-championship sequential decisions (Track A + Track B race strategy)"` |

**Not agent-visible:**
- **Evidence and verifier:** `manifest.json`, the verifier report and the `ping` reply gain `benchmark_version`. The sidecar `server_version` string becomes the benchmark version (it was `"b4-1"`).
- **`task.toml`:** `[task].version` 0.1.0 → 1.1.0.
- **Analysis runtime pin (local reproducibility only):**
  - `.python-version` = 3.12 and `scripts/py312` (runs analysis on Python 3.12 via uv).
  - Every replay and analysis entry point refuses other interpreters unless `F1_ALLOW_ANY_PYTHON=1` is set.
  - The reason: the sidecar and verifier images run Python 3.12.12. Python 3.12 changed float `sum()` to compensated summation, so on Python 3.9 the r2 journal from 1.0.0 fails its hash check at entry 11.
  - This changes nothing inside the images.

**Unchanged:**
- Mechanics, coefficients, event model, action space and legal actions
- Observations; no observation field changed
- `instruction.md`, the reward formula (`p0-provisional`), the journal format, and the hidden-seed handling

`devtests/test_version_interface.py` checks:
- **Observations:** a full season of observations contains no internal identifiers.
- **Rules:** internal identifiers appear only in the mapping table, and the published paces equal the engine's.
- **Historical replay:** the four 1.0.0 runs replay intact and regrade to their original rewards on Python 3.12.

**Why this is not a simplification.**
- **Before:** the information was already public in 1.0.0, under names the observations did not use. One agent (run r3) mapped two cars the wrong way round.
- **After:** the same information is stated unambiguously.
- **Unchanged:** the strategic problem is the same, and no hidden state, seed or future event is exposed.
